# Governance

This page says how the project is run today. It is short because the truth
is short.

1. **Who decides.** Scott Kalwei (`@kalwei`) is the maintainer and makes the
   decisions.
2. **How to propose a change.** Small things: open a pull request. Design
   changes: open an *Ideas* discussion using the template in
   [docs/decisions/TEMPLATE.md](docs/decisions/TEMPLATE.md); leave it open at
   least a week for comment. The accepted or declined outcome is merged as
   `docs/decisions/NNNN-title.md` with the reasons. Declined ideas stay
   searchable so nobody re-proposes them without new facts.
3. **What does not change by a pull request.** The licence (Apache-2.0 with
   the DCO), the six house rules in [CONTRIBUTING.md](CONTRIBUTING.md), and
   the provenance rule. Changing any of them needs a decision record with a
   30-day comment period.
4. **Roles.** Contributors are people with a merged pull request. Additional
   maintainers, if any, are listed in [MAINTAINERS.md](MAINTAINERS.md) with
   what they own. That file being short is a fact, not a problem.
5. **If the maintainer stops.** The code stays Apache-2.0; anyone listed in
   `MAINTAINERS.md` carries on; if nobody is listed, anyone may fork and
   continue under the same name.
6. **Conduct.** [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md); reports to
   conduct@factorysemantics.com.

If two more people become maintainers, one line is added here: decisions by
simple majority of maintainers, the founding maintainer breaks ties. Nothing
else changes until it has to.
