# 0.6.0

*Reference. What this release does, what it does not, and what is simulated.*

> **Not yet tagged.** This page is written before the tag so that the release
> body is reviewed rather than typed on release night. The date below is
> filled in when the maintainer tags it.

**Coming from 0.5.0? Five things on the screens are different:**

1. **The assistant's "Do it" works.** On a fresh 0.5.0 install it answered every change with an error ("database is locked"); it now makes the change.
2. **The cutlery plant's moulds have parts**: four heater bands and a melt sensor each, on Engineering › Master data › Equipment, where every row now says which cost center it pays into and where that comes from (on a cutlery plant built by 0.6.0: see below).
3. **A repair order can say which part it used** (a part code and a count) when it is closed, and the ERP books the part once.
4. **The Quality page** narrows non-conformances to one severity, lets a supervisor grade one when taking it under review, and shows which gauge took each reading. The hand-raise form offers the plant's own severities again.
5. **Engineering › Analysis** has "All machines": the whole plant on one list, worst OEE first. Each Export button now says which list it downloads.

**After the upgrade, start it** (`fsmes demo bottling`): the first start
backs up the database, brings it up to date and says so in one line. For a
plant of your own: `fsmes init-db --pack packs/yourplant`, or `--plant
yourplant` in a fleet. Two migrations, both additive.

**A cutlery plant made by 0.5.0 keeps its 0.5.0 machines.** It starts and
works, but the bands, the line cost centers and the 3D models are in the
new pack, and the demo keeps the copy it made. To see them, build a fresh one
beside it (the old one is left as it was):

```powershell
fsmes demo cutlery stop
fsmes demo cutlery --home "$env:LOCALAPPDATA\fsmes-0.6"
```

## What else is new, for a plant person who reads further

**Gauge studies (gage R&R): is it the gauge or the process?** A new screen,
Quality › Gauge studies, plans a study, takes its readings and gives the
verdict in a sentence, or says why it withholds one. It is the first module
a plant switches on (`[modules] gauge_studies = true` in its settings); the
cutlery pack has it on, bottling and machining do not.
[The changelog](https://github.com/factorysemantics/factorysemantics-mes/blob/main/CHANGELOG.md)
has the method and its refusals.

**Cost centers you can see.** Routing steps on Setup › Admin › Routings name
the cost center their machine bills to; every cutlery line has its own. A
pack's `equipment.json` may carry `cost_center`.

**Smaller fixes the walks found:** the Floor's quality check takes a reading
as measured (26.35, not rounded to 0.1) and says when the control chart
raised a hold; Book output fills its order list as you type the machine;
the Admin page names every box and jumps to each part; nothing hides under
the floating buttons; the Gauges page says "out of service" in words.

**For a simulated plant:** `wake_gap_seconds` (off by default) lets a paused
lab plant wake without playing the hours it was paused. An approved
adjustment is checked on the plant's own clock, so at ten times speed the
check comes in about half a minute.

## What 0.6.0 is not

- **Nothing talks to a real tag server yet.** No real plant has run any of
  this, as with every release before it.
- **The ERP books a part only through ERPNext**, and it has been tried only
  against a test ERPNext with a simulated company. There is no price or
  money in the MES.
- **The AI tab needs a key** (`ANTHROPIC_API_KEY`). The chat reads gauge
  studies; it does not plan them.
- **The cutlery scenes (hot mould, coil out) need a checkout.** `pip
  install` ships the bottling, machining and cutlery plants, not the scenes.
- **Everything in a lab is simulated**: the line simulator in
  `src/fsmes/sim/`, replayed over OPC UA.
